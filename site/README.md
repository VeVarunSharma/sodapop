# Sodapop website

The Soda shop landing page and documentation hub are a **private, static Astro
project**. Starlight supplies documentation navigation and Pagefind search;
selected shadcn/ui components use small React islands and Lucide icons.
There is no application backend, analytics, live model demo, or credential access.

## Work locally

Use a supported Node version (`.node-version` pins the CI toolchain), then run
these commands from the repository root:

```sh
npm --prefix site ci
npm --prefix site run dev
```

The build does not need Go or a Copilot runtime bundle. It reads only explicitly
selected documentation, artwork, and public distribution configuration.
Use an attached process for preview rather than leaving a detached server behind.

```sh
npm --prefix site run check
npm --prefix site test
npm --prefix site run build
npm --prefix site run check:artifact
npm --prefix site exec -- playwright install chromium
npm --prefix site run test:e2e
npm --prefix site run preview
```

Search is generated by the production build, not the development server.
The browser suite exercises the **built** site. To use a different preview port,
set `SODAPOP_SITE_PORT` for the browser suite.
If Chrome is already installed locally, `SODAPOP_SITE_BROWSER_CHANNEL=chrome`
uses it without downloading another browser. CI uses its installed Playwright
Chromium. Both paths create isolated test contexts, not a user's browser profile.

## Public sources, not a second documentation copy

Author documentation in root `docs/`. The explicit map in
`src/data/public-content.json` supplies public routes and navigation metadata.
`scripts/prepare-content.mjs` adapts the selected sources into the ignored
`src/content/docs/docs/` tree. Do not hand-edit that generated tree.

`scripts/prepare-assets.mjs` stages only approved brand artwork and recordings
under `public/assets/`. Do not copy the whole `images/`, repository, or dependency
directory there. Original artwork stays unchanged. The font is self-hosted from
its open-licensed package; locally licensed Avenir/Menlo font files are not shipped.

The recorded demos are signed out and use prepared local changes. They are not
live AI responses. GIFs use PNG posters until explicitly played; stopping restores
the poster. Keep these controls and the reduced-motion behavior intact.

## Pre-release and published downloads

`src/data/channels.json` defaults to an explicit **pre-release** state. That state
does not invent a version, download URL, npm command, or published tap. Source-build
guidance remains available with its actual prerequisites.

The release resolver is an explicit operator/CI action:

```sh
npm --prefix site run release:sync
npm --prefix site run build
npm --prefix site run check:artifact -- --public
```

Astro configuration validates the local catalog and injects a public-data-only
snapshot into the static routes. Page components use `src/lib/catalog.ts`;
do not call the filesystem reader from bundled pages, where `import.meta.url`
points into generated output instead of the source checkout.

When enabling release mode, configure the public repository and separately
published npm/Homebrew channels as defined in the channel configuration. The
resolver validates release and manifest identity, platform assets, and checksum
metadata before replacing the local resolved catalog. Failure must leave previous
valid metadata/deployment intact. The website never publishes an application
release, npm package, or tap formula itself.

For offline review when production configuration requires resolved release data:

```sh
SODAPOP_SITE_PREVIEW=1 npm --prefix site run build
```

Preview mode disables installation availability and marks the HTML as a
non-indexable preview. The public artifact gate rejects it. Do not deploy a
fixture or preview build as the public website.

## GitHub Pages

The dedicated workflow is `.github/workflows/pages.yml`. It builds both configured
and repository-prefixed variants, runs website-only checks, and uploads only
`site/dist/`. PRs and non-default branches use offline preview mode and cannot
deploy. Production uses the trusted default branch. A published-release event
requests a fresh workflow dispatch on that branch instead of deploying from the
release tag, which would fail a main-only Pages environment rule. Only that small
refresh job needs Actions write permission; build jobs remain read-only.
Existing native CI and release workflows remain independent.

Confirm the canonical repository, access, default branch, and reviewed source
files before enabling Pages. Do not stage the entire existing worktree to publish
the site. In repository Settings, select **GitHub Actions** as the Pages source
and configure the `github-pages` environment/protection rules.

The configured build reads `actions/configure-pages` metadata **before** building.
It derives the origin and base path from the actual Pages URL: a project site
uses its repository prefix, while a configured custom domain normally uses `/`.
No site variables are required. The second matrix build independently exercises
the repository-prefixed URL shape.

Optional repository variables act as explicit expectations for the configured
deployment. They must match Pages metadata; stale overrides fail before the build
instead of publishing broken links. Local builds still default to
`https://sodapop.sh` and `/`.

| Repository variable | Workflow default | Purpose |
| --- | --- | --- |
| `SODAPOP_SITE_URL` | Actual Pages origin | Optional expected HTTPS origin without a path |
| `SODAPOP_SITE_BASE` | Actual Pages base path | Optional expected root/repository path, such as `/sodapop/` |

For a repository-prefixed local build:

```sh
SODAPOP_SITE_URL=https://vevarunsharma.github.io \
SODAPOP_SITE_BASE=/sodapop/ npm --prefix site run build
SODAPOP_SITE_URL=https://vevarunsharma.github.io \
SODAPOP_SITE_BASE=/sodapop/ npm --prefix site run test:e2e
```

Domain verification, DNS, and HTTPS configuration require the domain owner's
authorization. Preserve unrelated DNS records and the existing OAuth application.
Do not assume a successful static build proves domain access or public releases.

The workflow, lockfile, site source, curated docs/assets, and referenced application
metadata must be committed and pushed before GitHub can run this pipeline. Once
the reviewed changes are on the default branch, a matching push starts it; it can
also be started with `gh workflow run pages.yml --ref main` when `main` is the
default branch. That dispatch can publish the website, not just build a preview.

To recover a website deployment, rebuild/redeploy a known-good website commit and
validated catalog through the protected workflow. Do not replace immutable native
release assets or roll back installer state to fix a website problem.

## Boundaries and contributions

Keep this package private and separate from `npm/`, which distributes the CLI.
Native archives and npm packages use their own explicit file allowlists; website
source, dependencies, and output must remain absent from both.

Use `site/AGENTS.md` for local guidance. The site has no remote content CMS or
runtime GitHub fetch: publication data is resolved explicitly before a build.
Never include tokens, OAuth payloads, environment files, or session/agent notes
in generated HTML, search, screenshots, or artifacts.

The component source under `src/components/ui/` was generated from shadcn/ui and
adapted to Sodapop's tokens/local class-name helper. Retain upstream licensing.
Do not replace the original Sodapop artwork with Charm, GitHub, or Copilot logos.
