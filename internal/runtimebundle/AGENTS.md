# Bundled runtime

Scope: `internal/runtimebundle/`. Apply the [repository rules](../../AGENTS.md) first.

## Rules and reasons

- Keep SDK and runtime pins explicit and separate. Keep `SDKVersion` aligned with
  `go.mod`; change pins deliberately, not by editing generated embedded assets.
- Resolve only the embedded native runtime and validate its required artifacts.
  Missing/invalid bundles must fail, never fall back to a user-installed executable.
- Preserve environment sanitization and explicit runtime state directories so
  inherited Copilot configuration or GitHub credentials cannot affect startup.
  Windows variable names are case-insensitive; mixed-case overrides must be removed.
- Support only `darwin/arm64`, `darwin/amd64`, `linux/arm64`, `linux/amd64`, and
  `windows/amd64`; an unsupported target must fail before bundling/building an
  unusable artifact.
- Keep ordinary tests on injected dependencies. Generated `zcopilot*.go` assets
  stay excluded from the handwritten coverage floor; testing generated bytes
  merely to raise coverage does not establish runtime correctness.
- A native process/protocol handshake is not an authenticated Copilot session.
  Keep native smoke and live qualification claims separate.

## Start here

[version.go](version.go), [runtime.go](runtime.go), and [runtime_test.go](runtime_test.go).
Follow [build/package guidance](../../scripts/AGENTS.md) when changing bundling.

## Checks

From the repository root: `go test ./internal/runtimebundle`.
For an explicitly needed native check, run `make bundle` before `make runtime-smoke`;
bundling needs network access. Do not regenerate assets for documentation changes.
